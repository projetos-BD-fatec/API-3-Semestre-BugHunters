# US05 - Preparação da Pré-Guia

| Prioridade | Sprint | Estimativa | Status |
| :---: | :---: | :---: | :---: |
| Alta | 1 | M | ⬜ |

## User Story

> Como responsável pelo FUSex, quero gerar a Pré-Guia com as informações da solicitação para deixá-la pronta para emissão.

## Critérios de aceitação

- [ ] A Pré-Guia pode ser gerada a partir de um encaminhamento analisado.
- [ ] A Pré-Guia contém a clínica e os procedimentos definidos para a solicitação.
- [ ] A Pré-Guia fica salva e pronta para a emissão da guia.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: preparação da Pré-Guia com as informações da solicitação.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: deixar a guia pronta para emissão.
- [ ] Os critérios de aceitação estão bem definidos e foram validados com o cliente.
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: campos que compõem a Pré-Guia, conforme o exemplo de guia do cliente.
- [ ] As dependências da história estão identificadas: US02 (encaminhamento analisado) e US04 (clínica e procedimentos).
- [ ] A equipe esclareceu as dúvidas sobre a história.
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.

## Definition of Done (DoD)

- [ ] A funcionalidade está desenvolvida e integrada ao sistema: Pré-Guia gerada a partir do encaminhamento analisado e gravada no banco.
- [ ] Todos os critérios de aceitação foram atendidos.
- [ ] A funcionalidade foi testada: gerar a Pré-Guia de um encaminhamento analisado e conferir a clínica e os procedimentos gravados.
- [ ] Os testes não apresentam erros críticos.
- [ ] A funcionalidade funciona conforme o fluxo definido: encaminhamento analisado → Pré-Guia pronta para emissão (US06).
- [ ] O código está versionado no repositório do projeto.
- [ ] A equipe revisou e validou a entrega.
- [ ] A funcionalidade está pronta para ser apresentada/demonstrada na Sprint Review.
