## User Story

> Como responsável pelo processo, quero processar os valores aprovados para concluir a liquidação do atendimento.

## Critérios de aceitação

- [ ] O responsável consegue selecionar as contas mensais com pagamento aprovado para liquidar.
- [ ] Ao processar, a conta e as guias dela passam a constar como liquidadas, com data e responsável registrados.
- [ ] Contas sem pagamento aprovado não podem ser liquidadas.
- [ ] Uma conta já liquidada não pode ser liquidada novamente.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: processamento dos valores aprovados da conta mensal para concluir a liquidação.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: encerrar o fluxo, registrando que o atendimento foi liquidado.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: o status final da conta e das guias após a liquidação e as regras para que a conta possa ser liquidada.
- [ ] As dependências da história estão identificadas: US14 (Aprovação do pagamento) e US16 (Fechamento por competência).
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: a liquidação no sistema é apenas o registro da conclusão (mudança de status) ou envolve integração com algum sistema de pagamento?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
