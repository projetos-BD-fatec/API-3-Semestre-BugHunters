# US01 - Registro do encaminhamento médico

| Prioridade | Sprint | Estimativa | Status |
| :---: | :---: | :---: | :---: |
| Alta | 1 | M | ⬜ |

## User Story

> Como responsável pelo FUSex, quero registrar o encaminhamento médico e os exames solicitados para iniciar o processo de atendimento.

## Critérios de aceitação

- [ ] É possível registrar um encaminhamento médico informando o beneficiário, o médico solicitante e a data da solicitação.
- [ ] É possível registrar um ou mais exames solicitados no mesmo encaminhamento.
- [ ] Campos obrigatórios não preenchidos impedem o registro e exibem uma mensagem ao usuário.
- [ ] O encaminhamento registrado fica salvo no banco de dados e pode ser consultado depois.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: registro do encaminhamento médico e dos exames solicitados.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: iniciar o processo de atendimento registrando o encaminhamento no sistema.
- [ ] Os critérios de aceitação estão bem definidos e foram validados com o cliente.
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: campos do encaminhamento (beneficiário, médico solicitante e data da solicitação), lista de exames e um exemplo de encaminhamento fornecido pelo cliente.
- [ ] As dependências da história estão identificadas: nenhuma, pois é o início do fluxo (as US02 e US05 dependem dela).
- [ ] A equipe esclareceu as dúvidas sobre a história.
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.

## Definition of Done (DoD)

- [ ] A funcionalidade está desenvolvida e integrada ao sistema: registro do encaminhamento e dos exames gravado no banco de dados.
- [ ] Todos os critérios de aceitação foram atendidos.
- [ ] A funcionalidade foi testada: registrar um encaminhamento com dois exames, tentar salvar com um campo obrigatório vazio e conferir o que foi gravado no banco.
- [ ] Os testes não apresentam erros críticos.
- [ ] A funcionalidade funciona conforme o fluxo definido: encaminhamento registrado → disponível para análise (US02).
- [ ] O código está versionado no repositório do projeto.
- [ ] A equipe revisou e validou a entrega.
- [ ] A funcionalidade está pronta para ser apresentada/demonstrada na Sprint Review.
