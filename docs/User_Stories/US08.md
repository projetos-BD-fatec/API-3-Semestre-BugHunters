## User Story

> Como responsável pelo FUSex, quero registrar as assinaturas necessárias na documentação para validar o encaminhamento.

## Critérios de aceitação

- [ ] É possível registrar as assinaturas necessárias na guia (médico e chefia do FUSex).
- [ ] Cada assinatura registrada indica quem assinou e quando.
- [ ] A guia só é considerada validada após o registro das assinaturas necessárias.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: registro das assinaturas necessárias na guia (médico e chefia do FUSex).
- [ ] O objetivo da funcionalidade está compreendido pela equipe: validar o encaminhamento.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: quais assinaturas são exigidas e quem deve assinar.
- [ ] As dependências da história estão identificadas: US06 (Emissão da Guia FUSex).
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: a assinatura é apenas o registro de quem assinou ou exige assinatura digital?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
