# US10 - Registro da realização

| Prioridade | Sprint | Estimativa | Status |

## User Story

> Como clínica/prestador, quero registrar a realização dos exames para que o atendimento fique registrado no sistema.

## Critérios de aceitação

- [ ] O prestador consegue registrar a realização dos exames de uma guia.
- [ ] O registro informa quais exames foram realizados e a data da realização.
- [ ] Após o registro, a guia passa a constar como realizada.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: registro da realização dos exames pelo prestador.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: deixar o atendimento registrado no sistema.
- [ ] Os critérios de aceitação estão bem definidos e foram validados com o cliente.
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: quais dados devem ser registrados na realização (exames realizados e data).
- [ ] As dependências da história estão identificadas: US06 (Emissão da Guia FUSex) e US09 (Consulta da Guia pelo prestador).
- [ ] A equipe esclareceu as dúvidas sobre a história.
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.

## Definition of Done (DoD)

- [ ] A funcionalidade está desenvolvida e integrada ao sistema: registro da realização gravado no banco e vinculado à guia.
- [ ] Todos os critérios de aceitação foram atendidos.
- [ ] A funcionalidade foi testada: registrar a realização dos exames de uma guia e conferir que exames e data ficam gravados e que a guia passa a constar como realizada.
- [ ] Os testes não apresentam erros críticos.
- [ ] A funcionalidade funciona conforme o fluxo definido: Guia consultada → exames realizados → realização registrada.
- [ ] O código está versionado no repositório do projeto.
- [ ] A equipe revisou e validou a entrega.
- [ ] A funcionalidade está pronta para ser apresentada/demonstrada na Sprint Review.
