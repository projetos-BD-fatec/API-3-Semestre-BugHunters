## User Story

> Como clínica/prestador, quero encaminhar digitalmente as guias e os documentos da realização para iniciar o processo de faturamento.

## Critérios de aceitação

- [ ] É possível criar um "Espelho da Guia" listando os itens (código do exame/insumo, descrição e valor cobrado) de uma guia já realizada.
- [ ] É possível adicionar itens ao espelho um a um, informando código, descrição e valor.
- [ ] O sistema valida se todos os itens têm código e valor preenchidos antes de permitir o envio.
- [ ] Ao confirmar o envio, a guia passa a constar como enviada ao FUSex e não pode mais ser editada pela OCS/clínica.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: criação e envio digital do Espelho da Guia (itens com código, descrição e valor) para iniciar o faturamento.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: permitir que a clínica informe os valores cobrados por item para dar início à conferência pelo FUSex.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: modelo de dados do Espelho da Guia (campos de cada item) e as regras de validação antes do envio.
- [ ] As dependências da história estão identificadas: US10 (Registro da realização), pois o espelho é gerado a partir de uma guia já realizada.
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: o código do exame/insumo usado no espelho é o mesmo da Planilha de Parâmetros (US03) ou um código próprio da clínica?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
