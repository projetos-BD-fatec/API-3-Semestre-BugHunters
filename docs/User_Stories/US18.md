## User Story

> Como responsável pelo FUSex, quero acompanhar em uma tela o fluxo completo e a etapa em que cada guia está, para ter visibilidade do processo desde a solicitação até a liquidação.

## Critérios de aceitação

- [ ] A tela mostra as etapas do fluxo na ordem (solicitação, emissão, realização, faturamento, Lisura e liquidação).
- [ ] Cada guia aparece na etapa em que está no momento.
- [ ] A listagem pode ser filtrada por etapa.
- [ ] Ao abrir uma guia, é possível ver as etapas concluídas e a data de cada uma.
- [ ] A tela reflete as atualizações feitas nas demais telas do sistema.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: tela com o fluxo completo e a etapa de cada guia, da solicitação à liquidação.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: dar visibilidade de em que etapa cada guia está e do que já foi concluído.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: a lista de etapas e status do fluxo e quais dados de cada guia devem aparecer na tela.
- [ ] As dependências da história estão identificadas: US01 a US17, pois cada etapa precisa registrar seu status para aparecer na tela.
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: a tela mostra apenas o status atual ou também o histórico de cada etapa?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
