# US14 - Aprovação do pagamento

| Prioridade | Sprint | Estimativa | Status |
| :---: | :---: | :---: | :---: |
| Média | 2 | P | ⬜ |

## User Story

> Como responsável pela Lisura, quero aprovar a solicitação após a conferência dos valores para autorizar o pagamento.

## Critérios de aceitação

- [ ] O analista consegue aprovar a Lisura, mudando o status da guia para aprovado para pagamento.
- [ ] O analista consegue recusar a Lisura, mudando o status da guia para glosado/recusado.
- [ ] A decisão fica registrada e visível no histórico da guia.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: aprovação ou recusa final da Lisura após a revisão dos valores.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: autorizar, ou não, o pagamento da guia com base na conferência já feita.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: os status possíveis da guia após a decisão (aprovado para pagamento / glosado).
- [ ] As dependências da história estão identificadas: US13 (Conferência dos valores).
- [ ] A equipe esclareceu as dúvidas sobre a história.
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
