# US13 - Conferência dos valores

> Esta User Story é a antiga US14 do backlog original, que já substituía as antigas US15 e US16 (unificadas em uma só). Após a renumeração do backlog, por causa da remoção da US13 (Integração com SisFat), ela passou a ser a US13.

## User Story

> Como responsável pela Lisura, quero comparar os valores apresentados com os valores previstos em contrato para identificar divergências.

## Critérios de aceitação

- [ ] O sistema compara, item a item, o valor cobrado no espelho com o valor previsto no contrato (Planilha de Parâmetros).
- [ ] Divergências entre os dois valores são destacadas visualmente para o analista da Lisura.
- [ ] O analista consegue acatar o valor do contrato ou informar um valor ajustado para cada item divergente.
- [ ] O valor revisado de cada item fica registrado no sistema.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: comparação dos valores cobrados pela clínica com os valores do contrato, item a item, com revisão pelo analista.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: identificar e tratar divergências de valores antes da aprovação do pagamento.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: a tabela de parâmetros/contrato (US03), com os valores previstos por procedimento.
- [ ] As dependências da história estão identificadas: US11 (Envio das guias e documentos) e US03 (Consulta à Planilha de Parâmetros).
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: o valor do contrato varia por clínica, ou é único por procedimento, independente da clínica?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
