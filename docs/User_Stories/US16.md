## User Story

> Como responsável pelo processo, quero processar os valores aprovados para concluir a liquidação do atendimento.

## Critérios de aceitação

- [ ] O responsável consegue selecionar as guias com pagamento aprovado e MAPA gerado para liquidar.
- [ ] Ao processar a liquidação, a guia passa a constar como liquidada, com data e responsável registrados.
- [ ] Guias sem pagamento aprovado ou sem MAPA gerado não podem ser liquidadas.
- [ ] Uma guia já liquidada não pode ser liquidada novamente.

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: processamento dos valores aprovados para concluir a liquidação de cada guia.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: encerrar o fluxo da guia, registrando que o atendimento foi liquidado.
- [ ] Os critérios de aceitação estão bem definidos (ver acima).
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: o status final da guia após a liquidação e as regras para que ela possa ser liquidada.
- [ ] As dependências da história estão identificadas: US14 (Aprovação do pagamento) e US15 (Geração do MAPA).
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: a liquidação no sistema é apenas o registro da conclusão (mudança de status) ou envolve integração com algum sistema de pagamento?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.
