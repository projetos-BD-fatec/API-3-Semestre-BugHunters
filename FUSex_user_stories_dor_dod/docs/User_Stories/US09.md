# US09 - Consulta da Guia pelo prestador

## User Story

> Como clínica/prestador, quero consultar os dados da Guia para realizar o atendimento do beneficiário.

## Critérios de aceitação

- [ ] O prestador consegue consultar os dados de uma guia emitida para ele.
- [ ] A consulta exibe as informações necessárias para o atendimento do beneficiário (beneficiário, exames e procedimentos autorizados).

## Definition of Ready (DoR)

- [ ] A User Story está claramente descrita: consulta da guia pelo prestador.
- [ ] O objetivo da funcionalidade está compreendido pela equipe: permitir que a clínica realize o atendimento do beneficiário.
- [ ] Os critérios de aceitação estão bem definidos e foram validados com o cliente.
- [ ] As informações necessárias para o desenvolvimento estão disponíveis: quais dados da guia o prestador precisa visualizar.
- [ ] As dependências da história estão identificadas: US06 (Emissão da Guia FUSex).
- [ ] A equipe esclareceu as dúvidas sobre a história. Confirmar com o cliente: a clínica acessa a guia com login próprio ou pelo número da guia?
- [ ] A User Story está priorizada no Product Backlog.
- [ ] A equipe consegue estimar o esforço necessário para desenvolvê-la.

## Definition of Done (DoD)

- [ ] A funcionalidade está desenvolvida e integrada ao sistema: tela de consulta da guia disponível para o prestador.
- [ ] Todos os critérios de aceitação foram atendidos.
- [ ] A funcionalidade foi testada: consultar uma guia emitida como prestador e conferir que os dados exibidos (beneficiário, exames e procedimentos autorizados) correspondem à guia.
- [ ] Os testes não apresentam erros críticos.
- [ ] A funcionalidade funciona conforme o fluxo definido: Guia emitida → consultada pelo prestador → atendimento (US10).
- [ ] O código está versionado no repositório do projeto.
- [ ] A equipe revisou e validou a entrega.
- [ ] A funcionalidade está pronta para ser apresentada/demonstrada na Sprint Review.
